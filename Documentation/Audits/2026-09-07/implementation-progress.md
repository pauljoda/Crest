## Measurement and current performance status

Use optimized, isolated `Crest Performance Soak` builds, six Spaces with 24 tabs and eight expanded saved folders each, and one explicitly loaded resident tab per Space. Disable the fixture's periodic title mutation in the temporary served copy identically before and after. Native input automation uses the already authorized Computer Use plugin. Stop automation while the user physically tests the app.

The initial implementation **did not meet the performance goal**. In the verified 12-switch, accessibility-assisted pair, baseline main-thread sampled weight was 25,753 ms over 40.876 seconds and candidate B was 29,231 ms over 40.975 seconds: 13.5% more sampled work. Every input and destination verification fit within its trace. Empty-extension options notifications disappeared from samples, but that local improvement did not produce a faster overall interaction.

The user then reported roughly a second before a swipe activated. A passive 30.866-second profile, with no automated input or accessibility queries, recorded ten potential hangs of 1.05–1.35 seconds. Main-thread sampled weight was 19,425 ms, including 16,395 ms under hosting layout and only 171 ms under accessibility. Real scroll-handler stacks were present. This confirms substantial layout work during physical use; it does not timestamp the user's initial finger movement.

Candidate C deferred unrelated neighbor preparation and preserved row identities when drag-source availability changed. It reduced main-thread sampled work in the same keyboard/accessibility-assisted workload to 12,850 ms over 40.928 seconds, but physical user feedback still rejected the interaction. Candidate D localized moving-list geometry observation and corrected active-folder ownership; it also failed user acceptance. These are not gesture-performance success claims.

A diagnostic-only E build captured eight real trackpad gestures. Event timestamp to accepted threshold was 20–63 ms, with the selection callback under 2 ms. Selection returned 72–133 ms before the pager observed it; the subsequent native draw milestone followed presentation by another 311–705 ms. Acceptance to that CPU-side draw milestone was 408–899 ms. Six gestures queued behind prior animation completions. All generations completed with their current selection; no cancellation or disabled-animation flags explained the missing motion. The two passive CPU recordings missed these eight gestures, so their stacks are not attributed to these event intervals.

This evidence changes the implementation direction: transient viewport progress must not depend on a committed browsing-state change or repeated SwiftUI offset layout. Apple's [native swipe tracker](https://developer.apple.com/documentation/appkit/nsevent/trackswipeevent(options:dampenamountthresholdmin:max:usinghandler:)) provides continuous progress, edge damping, cancellation and settling. Installed Arc/Dia class metadata also establishes dedicated native sidebar paging controllers and cached views, but reveals neither their source nor timing curves. A small native viewport around existing SwiftUI sidebar contents is being implemented and must pass real-input validation before acceptance.

Time Profiler samples and potential-hang intervals are not presented-frame timestamps, physical trackpad calibration, ordinary-user switch latency, or p50/p95/p99 animation results. Inclusive stack categories overlap. Address mutation appears to trigger an already pending synchronous graph flush; its inclusive cost does not establish that all flushed work belongs to address subscribers. Keep thermal state, process age, command timestamps and recording boundaries with the evidence.
