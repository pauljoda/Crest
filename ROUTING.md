# Routing: what to read for each kind of change

Crest is about 4,400 files, more than a contributor or a coding agent can hold
at once. Find the row for the change, open what it names, and skip what it
says to skip. Each `CONTEXT.md` is a short map of one folder: what it owns,
its children, what it depends on, and its rules, each pointing to the full
text. The rules themselves live in `AGENTS.md`, the `crest-contribution`
skill and `Documentation/`; these files only route to them.

The layout follows the Interpretable Context Methodology
([arXiv 2603.16021](https://arxiv.org/html/2603.16021v2)): a routing table
plus one context file per folder that groups work.

Reading order: this table, then the root [`CONTEXT.md`](CONTEXT.md), then the
`CONTEXT.md` of the folder you change, then the one document the row names.

| Task | Go to | Load | Skip |
| --- | --- | --- | --- |
| Shared tab, Space, window or history behavior | `CrestCore/CONTEXT.md` | `Documentation/Architecture/CoreArchitecture.md`, `CrestCore/README.md` | Swift views until the core intent exists |
| A new or changed core contract (intent, change, query, event) | `CrestCore/CONTEXT.md` | `Documentation/Architecture/ControlPlane.md`, then run `Scripts/control-plane/generate-contracts.sh` | hand edits to any `Generated` file |
| An engine command or event contract | `CrestCore/CONTEXT.md` | the Chromium row below: it regenerates `CrestContracts/include/crest_engine_contract.h`, an engine input | |
| Chromium engine inputs (patches, overlay, host header, prepare/apply/configure/build scripts) | `CrestEngines/Chromium/CONTEXT.md` | `CrestEngines/Chromium/README.md` ("Releasing"), `ForkMaintenance.md` | CrestMobile, `HelpCenter/` |
| The Chromium adapter in Swift | `CrestEngines/Chromium/CONTEXT.md` | `Documentation/Architecture/EngineAbstractionCompletion.md` | `Overlay/`, `Patches/` |
| A shared UI feature (sidebar, tabs, Spaces, settings) | `CrestShared/CONTEXT.md` | the feature folder, `CrestShared/DesignSystem/` before any new control | CrestCore internals |
| A Mac-only shell, window, Quick Window or system adapter | `CrestMac/CONTEXT.md` | `Documentation/ARCHITECTURE.md` ("Windows on macOS") | CrestMobile |
| WebKit page behavior | `CrestShared/CONTEXT.md` | `CrestShared/Infrastructure/WebKit/`, `CrestMac/Infrastructure/WebKit/` | the Chromium fork |
| Content blocking | `Documentation/Architecture/ContentBlocking.md` | `CrestCore/src/CrestCore/Application/ContentBlocking/`, the page adapter | other features |
| Link opening and popups | `Documentation/LinkOpeningPolicy.md` | `CrestMac/Features/QuickWindow/` | |
| Credentials and passkeys | `Documentation/ARCHITECTURE.md` ("Credentials and privacy") | `CrestShared/Features/Credentials/`, `CrestShared/Infrastructure/Credentials/` | |
| Sync and persistence | `Documentation/ARCHITECTURE.md` ("Data and synchronization") | `CrestCore/src/CrestCore/Application/Sync/`, `CrestShared/Infrastructure/Sync/` | UI features |
| The agent bridge (MCP tools) | `CrestMac/CONTEXT.md` | `CrestMac/App/Agents/`, `CrestAgents/`, `CrestAgentHelper/` | |
| Build settings or targets | `project.yml` | `CONTRIBUTING.md` ("Local setup") | `Crest.xcodeproj` (generated by XcodeGen) |
| A version bump or release note | `AGENTS.md` ("Versioning", "Explicit release notes") | `Config/Version.xcconfig`, `Documentation/ReleaseNotes.json` | everything else |
| Help Center or website copy | `HelpCenter/`, `Website/` | the page being changed | the app source |

## Always

- `AGENTS.md` and the `crest-contribution` skill: the rules every change follows.
- `Documentation/RepositoryGuardrails.md`: what the checks enforce.

## Never by default

- `Generated` folders and files marked `<auto-generated/>`: change the contract and regenerate.
- `Crest.xcodeproj`: edit `project.yml` and run `xcodegen generate`.
- `CrestShared/Resources/` asset catalogs, unless the change is an asset.
- The other platform's tree (CrestMobile for a Mac change, and the reverse) unless shared behavior moves.
